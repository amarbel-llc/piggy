# FDR 0006/0007 card day: the operator's tick sheet

Date: 2026-11-18. Status: a working note for one hand pass, not a design record.

This note lets the operator tick the piggy#303 hand pass (FDR 0006 phase (a))
quickly. The checklist itself is printed by the recipe and lives in the
`explore-fdr0006-a` header in the justfile; this note adds what each line

and piggy(1), **without running the pass**. Where a line says "expect", it is

## Before starting

- Run from a clean checkout of piggy master, not a feature worktree. The
  recipe runs `nix build .#default` there; nix sees only git-tracked files.
- **Step 2 provisions the card (`piggy card init`, `piggy card add-key`).
  Use a throwaway YubiKey, never a card you rely on.** `CARD=real` redirects
  nothing: the shell talks to the host's pcscd and your own agent, and every
  PIN and touch prompt is real.
- `CARD=real` starts no private agent and no software upstream. The
  `fdr-touch`, `fdr-remove`, `fdr-insert` and `fdr-stop-software` helpers
  exist only for `CARD=virtual`. Touch the card by hand; pull and replace it
  by hand; **step 6 (software keys through the piggy socket) does not apply**
  unless your own agent was started with an upstream.
- The recipe leaves you in a shell in `$FDR0006_DIR`; `cat $FDR0006_DIR/CHECKLIST` prints the list again.
  Exiting the shell removes the directory, so copy `grant.sig` and the
  attestation out first if you want them.

## What the prompts look like

An ordinary PIN prompt is titled `piggy PIV PIN`. When the agent asks for
your PIN, a notification titled `piggy-agent: PIN required` is sent for a
routine prompt, or `piggy-agent: operator act (<kind>) awaits your PIN` for an
operator act (when a notifier is configured).

The three operator-act dialogs differ by banner, window title and confirm
button (`contrib/piggy-askpass.sh`):

| Namespace | Title | Confirm button | Banner (text askpass) |
|---|---|---|---|
| `piggy-escalation-v1` | `piggy operator act: ESCALATION (grants authority)` | `Grant escalation` | `!!! OPERATOR ACT: ESCALATION — you are GRANTING AUTHORITY !!!` |
| `piggy-certificate-v1` | `piggy operator act: CERTIFICATE` | `Issue certificate` | `=== OPERATOR ACT: CERTIFICATE — you are certifying a key ===` |
| `piggy-quote-v1` | `piggy operator act: QUOTE` | `Sign quote` | `=== OPERATOR ACT: QUOTE — you are signing words already on record ===` |

Each shows the exact text being signed above the PIN field. With
`PROMPTS=real` and no GTK helper on PATH the dialog is zenity (which cannot
hold input, so operator acts need the GTK helper; RFC 0012 section 2.6). If
you see a plain PIN box with no banner for an operator act, that is a
failure: note it.

## Tick sheet

Step numbers are the checklist's.

1. **UX review.** Read the four `--help` pages and the two manpage sections.
   Tick when nothing is misleading. Note anything that is.
2. **Provision (throwaway card only).**
   - `piggy card init`: succeeds. The card asks for touch twice.
   - `piggy health --format tap`: per-slot policy points. Expect 9A pin
     once/touch cached and 9C pin always/touch always, and a point
     "can sign operator acts" that passes.
   - `piggy list --format=ndjson`: `pin_policy` and `touch_policy` per slot.
   - `piggy card export-attestation > 9c.attestation`: prints a PEM.
   - Second `piggy card init`: **refuses**, naming the card as provisioned.
   - `piggy card add-key 9c` on the occupied slot: **refuses** without
     `--replace`.
3. **Operator act.** `piggy operator-sign --namespace piggy-escalation-v1 < grant.txt > grant.sig`.
   - Expect: a PIN dialog showing the ESCALATION banner and your exact text,
     then a touch request, exit `0`, an sshsig on stdout.
   - `ssh-keygen -Y verify ...` prints `Good "piggy-escalation-v1" signature`.
   - Repeat with `piggy-certificate-v1` and `piggy-quote-v1`: each dialog has
     its own title, button and colour; escalation is the loudest.
   - A 4096-byte text: the dialog shows all of it, or the command **refuses**
     with `the operator-act text is too tall for the PIN dialog` (never a
     silently cut text).
   - `<b>markup</b>`, an `under_score` and a back`\`slash show literally.
4. **Misuse.** Each refuses, with the exit code piggy(1) names:

   | Command | Expect |
   |---|---|
   | `--namespace piggy-escalation-v1 --slot 9a` | exit `1`, refused by slot policy |
   | `--namespace git` | exit `1`, not an operator-act namespace |
   | `--namespace piggy-escalation-v1 < /dev/null` | exit `1`, no text |
   | `PIGGY_AUTH_SOCK=/nonexistent piggy operator-sign ...` | exit `3`, no agent serves operator acts |
   | `ssh-keygen -Y sign -f 9c.pub -U -n piggy-escalation-v1 grant.txt` | refused (the agent will not sign operator-act data on an ordinary request) |
   | `ssh-keygen -Y sign -f 9c.pub -U -n file grant.txt` | **allowed**, signs |

   The outcome's name is on stderr; "a refusal says why" means that line
   names the rule (slot policy, namespace, no text), not just a number.
5. **QA, break it on purpose.** Each is exit `4` ("not signed this time",
   asking again may succeed) unless noted:
   - cancel the PIN dialog: `cancelled`;
   - enter the PIN and do not touch: `cancelled` after the card's timeout;
   - enter the PIN, pull the card before touching: exit `4`;
   - pull the card, then ask: `card-absent` (exit `4`), or exit `1`, no key,
     once the agent has dropped the card's keys.
   Judge by eye: was there a visible notice when the card started waiting for
   the touch, where you were looking?
6. **Software keys.** Skip on `CARD=real` unless your agent has an upstream.
7. **Not covered by the automated lanes (yours to judge).** How the three
   dialogs look under the GTK helper; whether a long text shows whole; whether
   the touch notice reaches you; and the attestation chain to a Yubico root
   (`openssl verify -partial_chain -CAfile f9.pem attestation.pem`).
